# 证据与分析规则

按任务需要读取本文件。将分析用于决定做什么、为什么以及投入多少；不要为填满框架而增加页面。

## 导航

- 输入与价值还原：第 1–2 节
- 证据、指标与市场：第 3–5 节
- 框架、评分与反证：第 6–8 节

## 1. 完整处理输入，准确声明覆盖范围

1. 列出材料清单、版本、日期、来源及可访问状态，确定用户指定的主版本。
2. 读取全文、附录、批注和关键表格；检查提取是否遗漏图表、扫描页或被截断的内容。
3. 对录音建立时间段覆盖表：起止时间、处理方式、对应转写、关键议题、待核实片段。
4. 遍历全部时间段，不用摘要代替完整处理。复听产品定义、否定句、数值、争议点及低置信度片段。
5. 只有实际听取音频时才说“听过”。只读转写时写“基于完整转写”，并记录无法核验的音频部分。
6. 若无法取得原录音，完成可支持的分析，标注覆盖缺口；不要声称已还原会议全部意图。
7. 将会议原意、后续明确修正、分析者建议分别记录。以后续明确修正为准，保留时间戳或段落定位。
8. 只在缺口会改变产品定义或关键决策时提出具体问题；其余缺口进入待验证项。

覆盖记录示例：`材料 ID | 版本 | 已处理范围 | 处理方式 | 定位 | 缺口及影响`。

## 2. 先还原价值，再分析品类

对每个方案写一张“价值定义卡”，再搜索竞品与计算市场。不要从产品名称推断用途。

| 必填项 | 要回答的问题 |
|---|---|
| 用户与情境 | 谁在什么时刻、什么条件下使用？谁付款？ |
| 待完成任务 | 用户真正想取得什么结果，现有方式哪里失败？ |
| 核心机制 | 产品通过什么行为或能力改善结果？哪些能力不可替代？ |
| 价值衡量 | 时间、成本、错误、结果质量或情感价值如何被观察？ |
| 现有替代 | 不购买、人工服务、软件或已有设备如何完成同一任务？ |
| 初始边界 | 首发对象、场景、地域、渠道与必要功能是什么？ |
| 扩展条件 | 未来愿景成立前，需要先证明哪些用户行为或能力？ |

从用户任务拆出需求强度、发生频率、替代成本、采用摩擦与支付主体。情感价值也应寻找可观察行为，例如重复回看、主动保留或愿意付费；不要因为难量化就忽略。

区分“现在交付的结果”“下一阶段能力”“长期可选方向”。不要把愿景的全部市场计入首发产品，也不要将首发边界误写为长期上限。

## 3. 建立可追溯的证据链

按“结论 → 支撑论据 → 原始来源 → 适用边界”组织证据。优先核实可能改变选择的关键主张。

| 标签 | 含义 | 页面表达 |
|---|---|---|
| 已核验事实 | 来源能够直接支持、口径已确认的信息 | 明确指标、期间与来源 |
| 主体披露 | 公司、用户或其他主体的陈述，独立验证有限 | 写“公司披露”“受访者表示”等 |
| 分析推断 | 从已知证据推导出的判断 | 写明推导与可推翻条件 |
| 假设或情景 | 用于计算、设计或比较的输入 | 明确“假设”“情景”，列范围 |
| 决策或建议 | 希望采取的行动 | 区分已批准事项与待决议建议 |

每条关键来源记录：`来源 ID、发布者、标题、发布日期、数据期间、地域、单位、分母或样本、指标定义、原文定位、链接或材料定位、限制、访问日期`。

优先顺序根据问题选定：正式统计、财报及监管文件、原始研究、产品官方材料、可靠独立报道、平台观察。官方宣传同样可能只代表主体陈述。

打开原始来源核查上下文，不以搜索摘要作为最终凭证。多篇转载同一新闻稿只算一条证据。无法验证的数字不能因反复出现而升级。

对关键主张同时检索支持与反对材料。记录“未公开披露”“暂未找到”“不适用”，不要把缺失数据写成零。

## 4. 先统一指标，再画比较图

逐项检查期间、地域、单位、对象、统计范围、总额或净额，以及实际、预测或累计口径。

- 区分出货、渠道进货、终端销售、激活设备、活跃用户、付费用户与账户数。
- 区分累计销量与当年销量、订单与完成交易、GMV 与收入、ARR 与当期确认收入。
- 区分订阅存量变化与同一批用户续费率；总收入增长不能直接证明用户留存改善。
- 区分平台显示量、抽样估计与可审计销量；说明覆盖渠道及外推限制。
- 区分价格标价、实际成交价与扣除税费、退货、分成后的收入。
- 同时检查有张力的配对指标，如收入与付费人数、增长与获客成本、销量与毛利。

不能可靠统一口径时，分栏展示并加注，不强行排序或相加。计算变化率时保留基期与公式；基期为零时不报普通同比百分比。

## 5. 用市场边界与底层模型支持空间判断

先声明地域、目标人群、用途、时间跨度、收入口径与产品边界，再估算市场。

| 层次 | 建模原则 | 常见错误 |
|---|---|---|
| TAM | 在明确边界内，可购买该结果的需求总量 | 直接采用相邻大行业总额 |
| SAM | 当前产品、渠道、地域与交付能力能够服务的部分 | 只乘一个主观百分比 |
| SOM | 在给定期间和资源下可能获取的量 | 用市场份额愿望代替获客模型 |

按商业模式选择自下而上的公式，并保证量纲一致：

- 一次性硬件收入：期间内购买人数 × 每人购买台数 × 单台净收入；存量、替换与新增分别处理。
- 订阅收入：平均付费账户数 × 每账户期间净收入；处理新增、流失及年中加入影响。
- 交易净收入：完成交易次数 × 平均成交额 × 净变现比例；不把交易总额直接当收入。
- SOM：可触达客户 × 有效转化率，再受产能、资金、渠道与服务容量约束。

逐个标注参数来源，给出合理范围及最敏感的参数。无依据的参数留空或明确为待验证假设。

用相邻品类数据验证采用行为、支付意愿或供应链成熟度；不要据此声称本产品需求已被验证。

将趋势拆成“变化 → 用户结果或成本变化 → 采用条件 → 竞争反应”。技术进步既可能扩大需求，也可能降低差异化与进入壁垒。

若只知道目标收入和单价，可反推所需销量作为“规模门槛情景”；明确它不是市场预测。

## 6. 选择能改变判断的经典框架

| 决策问题 | 可选框架 | 必须产出的具体结论 |
|---|---|---|
| 为什么用户需要？ | 第一性拆解、JTBD | 核心结果、替代方案与采用摩擦 |
| 先服务谁？ | STP、细分市场比较 | 首发客群、排除对象与定位依据 |
| 为什么现在可进入？ | 趋势与情景分析 | 变化机制、成立条件与风险窗口 |
| 利润由谁获取？ | 五力、价值链 | 议价权、控制点、依赖与利润压力 |
| 我们凭什么赢？ | 能力差距、资源优势分析 | 已有优势、待补能力、合作或自建 |
| 应投入到哪一步？ | 阶段验证、实物期权视角 | 最小合理承诺、通过标准与停止条件 |

不要机械套满所有框架。每采用一个框架，明确它改变了哪个选择；不能产生选择差异时，省略该框架页面。

## 7. 让评分可解释，并与投入决策分开

1. 先明确评分服务于什么目标：短期现金、长期能力、增长或其他目标；不要隐含混用。
2. 使用相同定义、期间与粒度比较方案。核心机制不同的产品配置应分别评估。
3. 分开表达“机会吸引力”“本方进入准备度”“证据置信度”；置信度不直接等于市场吸引力。
4. 先定义维度、权重及等级锚点，再评分。依据真实参照或可观察条件校准，不为得到高分调整规则。
5. 将未知标为未知，不自动记为低分。披露缺失权重；缺口影响结论时，展示范围并暂停精确总排名。
6. 若计算总分，展示公式与关键权重，检验合理权重变化是否改变排序；不稳定时明确说明。
7. 若用 A–D 等级，解释每级含义。不要将 A 自动解释为已批准投入，也不要凭空给成功概率。
8. 单独列出不可被高总分抵消的硬门槛，例如交付能力、单位贡献或用户接受度。

给每个方案补一句“什么新证据会让这个评级上升或下降”。不要使用小数位制造判断精度。

## 8. 用反证与下一步承诺闭合分析

对每个建议提出最强替代解释、关键失败条件，以及最便宜且能区分解释的验证方式。

必要时比较：原有行为、相同服务但无新增产品、完整新方案；尽量保持样本和服务质量可比，避免把服务效果归给硬件。

无法观察核心体验时，允许先做必要原型；不要把所有探索强制排成串行。原型预算、规模化单位经济与现金需求分别核算。

将结论写成：`建议行动 → 支撑证据 → 仍未证明的条件 → 下一阶段产出 → 通过/停止标准 → 所需资源`。资源与门槛应来自任务约束或明确假设，不凭空设定审批上限。
